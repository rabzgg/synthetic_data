# Events and scenarios

_Generated by `python3 cli/events_doc.py` from `core/events/`, `configs/scenarios/` and `configs/devices/`; do not edit by hand._

An event changes the world (its drivers or the body's motion; the world then derives RH, O2, pressure and the body tracks again) or one device (what its sensors are given, its states, its connection). It never writes a CSV column. Whether a device can see an event follows from what the event affects and what the device measures, which features it has and where it is mounted; an event no device of a run can see is refused with the reason.

## Events

### `gas_release`: Gas release

A gas leaks into the air around the devices, holds at a level for a while, then clears.

- Changes: the world; reaches every device that measures what it affects.
- Affects: `air.h2s_ppm`, `air.o2_pct` (with the default gas)

| parameter | default | unit | source |
|---|---|---|---|
| `gas` | h2s | - | ASSUMPTION: default gas |
| `level` | 20 | gas unit | ASSUMPTION: a level that crosses typical alarm setpoints |
| `duration_s` | 600 | s | ASSUMPTION: time at the level |
| `ramp_s` | 30 | s | ASSUMPTION: the gas builds up and clears over half a minute |

## What the labels say

Each run writes, per device, the events it saw (scope `world` or `device`) and what the device should do in response (scope `expected`):

- **No motion** (device feature `motion_alerts.no_motion`): after `detect_s` without any movement a `no_motion_pre_alarm` to the wearer for `pre_alarm_s`, then a `no_motion_alert`, until the body moves again.
- **Fall** (feature `motion_alerts.fall`): a `fall_pre_alarm` from the moment the wearer lies at rest, for `pre_alarm_s`; getting up within it cancels it, otherwise a `fall_alert` until the wearer gets up.
- **Collapse**: `collapse:gas_release` → `collapse:fall` → `collapse:stir` (moves a little, `no_motion_after_s`) → `collapse:no_motion` (`no_motion_s`) → `collapse:rescue`; the gaps are parameters.

## Which device sees which event
